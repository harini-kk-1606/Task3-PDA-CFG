## 1. Aim

To select context-free language applications, define their languages, construct CFG models, explain corresponding PDA behaviour, and validate accepted and rejected strings. The three selected case studies are balanced parentheses, arithmetic-expression syntax, and palindromes over a binary alphabet.

## 2. Background

A context-free grammar is a tuple `G = (V, Σ, P, S)`, where `V` is the set of variables/non-terminals, `Σ` is the terminal alphabet, `P` is the set of productions, and `S` is the start symbol. A pushdown automaton adds a stack to finite control. The stack allows a PDA to represent nested structure or remember a prefix for later comparison. CFGs and nondeterministic PDAs describe exactly the context-free languages.

A finite automaton has only finite control and cannot store an arbitrarily large number of unmatched opening brackets or an arbitrary first half of a palindrome. The stack is therefore essential for the first and third case studies.

## 3. Case Study 1 — Balanced Parentheses

### 3.1 Target language

`L₁ = { w ∈ {(,)}* | every prefix has at least as many '(' as ')', and the total counts are equal }`.

### 3.2 CFG

`G₁ = ({S}, {(,),}, {S → (S)S, S → ε}, S)`.

The production `(S)S` creates one matched outer pair containing a balanced string, followed by another balanced string. `ε` permits the empty string.

### 3.3 PDA strategy

Use a bottom-of-stack marker `Z₀` and a stack marker `(`. For each input `(`, push `(`. For each input `)`, pop one `(`. Reject if a `)` is read while only `Z₀` remains. At end of input, accept if only `Z₀` remains; otherwise reject. This is a deterministic stack strategy for this one-bracket-type language.

### 3.4 Worked trace

Input: `(()())`

| Step | Read | Stack action | Stack after action |
|---:|:---:|---|---|
| 0 | — | Initialize | `Z₀` |
| 1 | `(` | Push | `Z₀ (` |
| 2 | `(` | Push | `Z₀ ( (` |
| 3 | `)` | Pop | `Z₀ (` |
| 4 | `(` | Push | `Z₀ ( (` |
| 5 | `)` | Pop | `Z₀ (` |
| 6 | `)` | Pop | `Z₀` |
| 7 | END | Bottom marker only | ACCEPT |

### 3.5 Test cases

| Input | Expected | Reason |
|---|---|---|
| `()` | Accept | One matched pair |
| `(()())` | Accept | Correct nesting |
| `()()` | Accept | Two consecutive pairs |
| `ε` (empty input) | Accept | Generated by `S → ε` |
| `((())` | Reject | One unmatched opening bracket |
| `())` | Reject | Closing bracket underflow |
| `)(` | Reject | Closing bracket appears first |
| `(a)` | Reject | `a` is outside the alphabet |

## 4. Case Study 2 — Arithmetic Expression Validation

### 4.1 Target language

The language consists of syntactically valid expressions formed from identifiers, numeric literals, parentheses, and binary operators `+`, `-`, `*`, `/`. Whitespace is ignored. Multiplication and division have higher precedence than addition and subtraction; operators at the same precedence level are parsed left-associatively.

### 4.2 CFG

```text
E  → T E′
E′ → + T E′ | - T E′ | ε
T  → F T′
T′ → * F T′ | / F T′ | ε
F  → (E) | id | num
```

`E` handles addition/subtraction, `T` handles multiplication/division, and `F` handles parenthesized expressions or atomic operands. This layered grammar encodes precedence and avoids the common ambiguity of a single flat expression rule.

### 4.3 PDA / parser strategy

A PDA can recognize the context-free syntax. A practical parser uses a stack of pending grammar symbols or a recursive-descent call stack. The implementation uses recursive-descent procedures `E()`, `T()`, and `F()` corresponding to the productions. Parentheses cause recursive parsing of an inner `E`.

### 4.4 Worked derivation

Input: `a + 2 * b`

```text
E
⇒ T E′
⇒ F T′ E′
⇒ id T′ E′
⇒ id E′
⇒ id + T E′
⇒ id + F T′ E′
⇒ id + num * F T′ E′
⇒ id + num * id T′ E′
⇒ id + num * id E′
⇒ id + num * id
```

The grammar parses `2 * b` as a `T` term before combining it with `a` using `+`.

### 4.5 Test cases

| Input | Expected | Reason |
|---|---|---|
| `a + 12 * b` | Accept | Valid precedence structure |
| `(x + 2) * 5` | Accept | Parenthesized expression |
| `num / (a - b)` | Accept | Valid nested expression |
| `a+b/c-d` | Accept | Valid operator sequence |
| `a + * b` | Reject | Missing operand after `+` |
| `(a + b` | Reject | Missing closing parenthesis |
| `a b` | Reject | Unexpected adjacent operand |
| `*a` | Reject | Expression cannot start with `*` |

### 4.6 Ambiguity and limitations

A flat grammar such as `E → E + E | E * E | id` is ambiguous because an expression such as `id + id * id` can have different parse trees. The layered grammar above encodes precedence and associativity, resolving that ambiguity for the chosen operators. The validator checks syntax only; it does not evaluate the expression, check division by zero, resolve variable declarations, or perform type checking.

## 5. Case Study 3 — Palindrome Checker

### 5.1 Target language

`L₃ = { w ∈ {a,b}* | w = wᴿ }`, where `wᴿ` is the reverse of `w`. Both even- and odd-length palindromes are included.

### 5.2 CFG

`G₃ = ({S}, {a,b}, {S → aSa, S → bSb, S → a, S → b, S → ε}, S)`.

The recursive rules add matching symbols at both ends. The base productions `a`, `b`, and `ε` terminate the derivation and support odd and even lengths.

### 5.3 NPDA strategy

The PDA nondeterministically chooses where the midpoint occurs. Before the midpoint, it pushes each symbol. It then makes an ε-transition to a matching phase. In the matching phase, it reads each remaining symbol and pops the stack; the input symbol must equal the popped symbol. It accepts when the input is consumed and the stored first half has been matched. For odd-length strings, the guessed midpoint transition can consume the one central symbol before matching begins (equivalently, the PDA can nondeterministically skip one middle symbol).

### 5.4 Worked example

Input: `abba`

- Push `a`, then push `b` while reading the first half.
- Guess the midpoint after the second symbol.
- Read the next `b`; pop and match `b`.
- Read the final `a`; pop and match `a`.
- Input is exhausted and the stack is empty: accept.

For `aba`, the midpoint choice skips the central `b`; then the PDA matches the final `a` against the first `a`.

### 5.5 Test cases

| Input | Expected | Reason |
|---|---|---|
| `ε` (empty input) | Accept | Empty string is a palindrome |
| `a` | Accept | One-symbol palindrome |
| `abba` | Accept | Even-length palindrome |
| `aba` | Accept | Odd-length palindrome |
| `babab` | Accept | Odd-length palindrome |
| `aab` | Reject | Reverse differs |
| `abab` | Reject | Reverse differs |
| `abb` | Reject | Reverse differs |
| `abc` | Reject | `c` is outside the alphabet |

### 5.6 Determinism and limitations

The midpoint is not marked in the input, so an NPDA can guess it nondeterministically. A deterministic one-stack PDA cannot recognize the full language of palindromes over `{a,b}` without a separator because it cannot know when to switch from pushing to popping. The web simulator tests all possible midpoint positions conceptually and displays a successful split when one exists; it is an educational NPDA simulation rather than a literal transition-by-transition machine implementation.

## 6. Why finite automata are insufficient

- Balanced parentheses can require arbitrarily deep nesting. A finite automaton has finitely many states and cannot remember an unbounded number of unmatched opening brackets.
- Palindrome recognition requires remembering an unbounded prefix and comparing it with the suffix in reverse order. A finite automaton has no unbounded memory.
- Arithmetic expressions can contain arbitrarily nested parentheses, requiring stack-like memory. A finite automaton cannot generally validate arbitrary nesting depth.

## 7. Comparison

| Case study | CFG feature | PDA feature | Practical limitation |
|---|---|---|---|
| Parentheses | Recursive nesting | Push/pop matching | This project models one bracket type |
| Arithmetic | Precedence and recursive grouping | Parser stack | No semantic/type analysis |
| Palindrome | Matching terminals at both ends | Nondeterministic midpoint | Midpoint is guessed; simulator checks candidate splits |

## 8. Conclusion

The three case studies show how CFGs describe recursive language structure and how PDAs use stacks to recognize context-free patterns. Balanced parentheses use stack push/pop operations, arithmetic syntax uses grammar-directed parsing, and palindrome recognition illustrates nondeterministic midpoint selection. The project also shows why finite automata are insufficient for these unbounded structures and identifies the practical limitations of each model.
